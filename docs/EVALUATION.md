# Evaluation evidence

Independent portfolio project. All fixtures and observations in this document are fictional/sample data.

## Intermittent failure

Run `uv run python -m demo.scenarios`. This generates each answer through the normal provider, applies the YAML checks, stores SQL reports, compares promoted references and delivers local failure alerts.

The `mock/ticket-classifier-intermittent` variant lowers the priority of a team-wide outage on every third attempt. For three attempts, `shared-outage` changes from 3/3 to 2/3. The aggregate loses 1⅔ points, and the critical gate fails.

The tradeoff scenario first collects an intentionally weaker reference with three incorrect standard invoice classifications. Its candidate repairs those cases and introduces one critical failure. The mean improves from 85 to 98⅓ while the critical gate still fails. These values describe the scripted fixture. The script asserts the resulting decisions and restores the healthy reference afterward.

Fault-injection models receive only the prompt, input, params and attempt index. Case IDs, severity and answer keys never enter the provider. The original JSON-format break remains available through `demo/break_it.py`.

## Held-out evaluator calibration

Run `REGRESSGUARD_SEMANTIC_BACKEND=tfidf uv run python -m demo.calibrate`. The development set contains 10 authored labeled pairs. It fits the reference vocabulary/IDF and selects among thresholds 0.60, 0.70, 0.80, 0.90 and 0.95 by development errors, then misses, then distance from 0.80. Only after selection does the command open the separate 24-pair holdout set. Tests verify that changing holdout labels cannot change the selected threshold or representation.

Labels and the reason for each label are committed next to every candidate. These are authored synthetic challenge pairs, with no independent human annotation or hosted model provenance. Dataset hashes and complete case-level outputs appear in the [generated report](calibration/report.md) and [machine-readable evidence](calibration/report.json).

The measured threshold was 0.80. On the 12 unacceptable holdout outputs, cosine alone flagged five and missed seven. With negation and numeric guards, it flagged nine and missed three. Both modes rejected four of the 12 acceptable outputs. These small counts describe this fixed challenge set and have no claimed population accuracy.

The missed failures include swapped entities, shifted negation scope and spelled-out number changes. False alarms include valid paraphrases and equivalent negative phrasing. The guard is conservative: it compares marker counts and numeric values. It cannot establish entailment. Schema checks, domain assertions and calibrated judges supply additional evidence where those facts matter.

## Evaluator version changes

Evaluator version 2 rejects numeric overflow and changes TF-IDF handling of unseen tokens. Semantic checks default to `preserve_facts: true`. Set it explicitly to false to measure cosine alone. Its setting belongs to the evaluation contract.

Earlier runs and snapshots retain their serialized contracts. A version-1 baseline cannot be compared locally with version 2. Collect and review a fresh reference with the current evaluator, then promote/export it explicitly. The demo's version-2 snapshots were generated by actual runs. The API never silently overwrites an existing promotion during startup.

For a local database created by the previous demo:

```sh
uv run regressguard run --suite suites/ticket-classifier.yml --runs 3
uv run regressguard baseline --run <printed-run-id>
uv run regressguard run --suite suites/summarizer.yml --runs 3
uv run regressguard baseline --run <printed-run-id>
```

In Compose, prefix commands with `docker compose exec api .venv/bin/` and omit `uv run`. Retain earlier evidence for inspection.

## Interpreting repeated samples

Three samples can expose an intermittent defect. They give weak precision about an unknown failure probability. The demo repeats are scripted and correlated. The release policy remains a specified critical-case gate and an exact observed-score threshold. It makes no statistical-significance claim. Calibration evaluates individual labeled outputs; it does not estimate the false-block rate of a deployment workflow.

## HTTP integration evidence

The transport smoke command starts a loopback server and sends real HTTP requests through the compatible client and webhook delivery code. It checks generation, a baseline comparison, judging, missing usage, auth errors, malformed envelopes and exact alert-payload parity across HTTP, SQL and JSONL. It also asserts that the local test credential is absent from persisted reports and alerts. These are scripted server responses, with no claim of hosted-model evaluation. The separate command keeps default pytest network-free.
